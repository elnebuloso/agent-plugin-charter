# Frontend after the design is agreed

The project's visual design is agreed and written down in `<DESIGN_FILE>`. The frontend is built
to it; taste of your own has no part in it.

- **Only the file's values.** Colours, type, spacing, radii, borders, shadows and components come
  from `<DESIGN_FILE>` — no value of your own, not even one close to one it names.
- **What the file leaves open is asked, not invented.** A screen, state or value it does not cover
  goes to the user; their answer is added to `<DESIGN_FILE>` before the code that needs it.
- **The file changes only on the user's word.** Code that does not match it is changed, not the
  file.
- **Design skills stay off.** Load no design, styling or animation skill for frontend work, even
  when its description matches — unless the user asks for one by name; the file's values still
  win over what it suggests.
- **Click dummies built to find a new design are exempt.** They exist to replace this one.
